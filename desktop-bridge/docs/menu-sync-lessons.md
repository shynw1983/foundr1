## 命名原则

1. Uber 是已配置源的权威原文。OS 保留结构化语言字段及稳定运营 ID；修改下游展示名不能反写 Uber/OS 原文。
2. 保留当前平台投影的语言、顺序和分隔；没有触犯已确认限制的语言段不得因一次改名被删掉或换成别的语言。
3. 份量、单位、数字顺序、日期、价格条件、原料和商品身份必须保留。AI 的 `safe: true` 不是跳过本地安全检查的凭证。
4. `〜` / `～` 的含义由语境决定，可能是起价、区间或装饰。不能建立全菜单统一的 `から` / `kara` 替换。
5. 名称、价格、库存、分组关系分别核对。名称修改不得恢复销售、释放新建商品保护、重新创建已有对象或借改名移动分组。
6. 泛化的 HTTP 400 / `MWA0012` 不能被解释为“名称有错”；认证、超时、网络、价格、库存和身份错误也不能触发改名。

## 每次同步问题处理后的交付清单

1. **案例**：写日期、平台/字段、现象、确认原因及仍未知的部分；不保存密码、Cookie、token、原始 AI 回复或推理。
2. **规则**：说明适用品牌/源/字段和失效条件。源名称或平台规则变化后必须重新核对。
3. **常规入口**：确认修复是否在 OS 发起 → Bridge 正常任务 → 平台保存 → 原生回读的共同流程。仅人工改单或临时脚本不是程序修复。
4. **回归**：在对应共享检查、AI 安全、事务、Bridge 或发布测试中覆盖案例；包含身份冲突、未识别对象和不安全候选的拒绝行为。
5. **学习**：只在正常完整验收后确认精确候选；失败和诊断保留，不能覆盖成成功。名称经验不改变库存或新建保护。
6. **实际生效**：分别记录代码/测试完成、OS 服务端部署、Mac runtime 安装、运行文件哈希及启动后健康验证。未经授权或未实际发布须明确写“待发布”，不能只凭源码存在宣称生效。
7. **验收边界**：后台内容回读不等于顾客 APP 可下单，也不等于完整库存审计。保留原有隔离对象，不为了全绿取消保护。

新增经验按以上清单追加，不把一次恢复写成“以后所有平台永不出错”。未确认规则只做线索；经验证且授权的规则才进入共享程序。OS 自动同步保存精确候选及任务结果，但不会自行把一次泛化错误升级成新的平台禁用规则。
