# 外部プラットフォーム・メニュー配信

Foundr1 OS の `/os/menus` を商品名、説明、価格、公開状態、選択肢構成の正本とする。
Web予約は共通メニュー API を直接参照し、Uber Eats、Rocket Now、出前館は Desktop Bridge が各管理画面へ差分を反映する。

## 配信手順

1. Desktop Bridge が対象店舗の各プラットフォームから現在メニューを回読する。
2. OS が安定した外部 ID と OS の商品・選択肢 ID を対応付ける。
3. ルールのバージョンを固定して、追加・名称・価格・配置・停止・削除候補の差分を作る。
4. 操作者が店舗と配信先を選択する。停止・削除候補は追加確認を必須とする。
5. Bridge が差分を反映し、同じ対象を回読して一致した場合だけ成功にする。
6. タイムアウト、ログイン切れ、対象不一致、UI変更は失敗として保存し、再試行できるようにする。

基準取込で対象が一意に見つからない場合は完全な基準として扱わず、構造変更の配信を停止する。文字列の部分一致だけで商品を推測しない。

基準取込は OS の既知商品だけを検索する方式ではなく、プラットフォームに表示される商品・選択肢を全量列挙する。OS に存在しないデータは「プラットフォームで見つかった OS 未登録データ」として保存し、次から選択する。

- OS に未公開の商品下書きを作る
- プラットフォーム専用として保持する
- 後で再確認する

既存商品の名称・価格・販売状態がプラットフォーム側で直接変更されていた場合は、差分ごとにプラットフォーム現在値を個別設定へ取り込める。自動的に OS 共通値を上書きしない。

毎日 08:00 の全プラットフォーム在庫同期後に、同じ店舗の全メニュー回読も自動でキューへ追加する。共有アカウントでは変更者本人を特定できないため、検出プラットフォーム、初回検出時刻、最終確認時刻を履歴として保持する。

## 現行ルール

| 配信先 | 名称・言語 | Emoji | 価格 | 構成上の制約 |
| --- | --- | --- | --- | --- |
| Web予約 | OS の `displayNames` を言語別に表示 | OS のWeb表示設定 | OS基本価格 | ブランドサイトは標準公開メニュー API を使用 |
| Uber Eats | 日本語・簡体中文・韓国語・英語を `｜` で連結 | 使用可 | OS基本価格の1.25倍、商品別上書き可 | 外部IDを保存して回読確認 |
| Rocket Now | 日本語のみ | 原則除去 | OS基本価格の1.25倍、商品別上書き可 | 選択肢上限に合わせて standard topping などを分割 |
| 出前館 | 日本語・簡体中文・韓国語・英語を `｜` で連結 | 原則除去 | OS基本価格、商品別上書き可 | 通常麺・変更麺・冷麺の配置規則を検証 |

ルールは `menu_external_platforms.rule_version` と `rule_config` に保存する。配信バッチは開始時点のルールバージョンとプレビューを保持し、後から規則を変更しても履歴の意味が変わらないようにする。

## 個別設定

商品・選択肢ごとに、各プラットフォームについて次を上書きできる。

- 販売する／しない
- 名称
- 説明
- 価格
- Emoji の表示方法
- 配置・分割用のプラットフォーム固有設定

上書きがない項目は共通ルールから自動生成する。プラットフォームごとに同じ商品を複製して管理しない。

## Bridge の安全条件

- タブレット Bridge は接注専用とし、メニュー・在庫同期コマンドを受け取らない。
- メニュー変更と基準取込は Desktop Bridge だけが実行する。
- Bridge が未対応の変更種別は `menu_action_unsupported` として失敗させ、成功扱いにしない。
- ページ構造が変わった場合は `platform_ui_changed`、一意に特定できない場合は `menu_target_verification_failed` として停止する。
- 反映後の回読値が予定値と違う場合は成功にしない。
