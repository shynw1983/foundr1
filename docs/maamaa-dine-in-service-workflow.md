## 门店执行规则

“菜碗”是顾客自选食材用的大碗，不是托盘；提供用成品碗没有永久号码。每碗独立取餐号，厨房票、出品票和顾客叫号票同号。收银条按付款交易出，不承担识别每位顾客的职责。

2026-10-17 门店确认：牛筋、猪软骨等另收费的贵价食材由厨房按所售份数添加，不在收银台加入称重碗。收银记录每碗的选择、50g 份数和追加价格，厨房按厨房票／出品票执行；自选食材的净重与这些追加项分别计价。

2026-10-18 备妥的快捷去皮：后台 `/os/pos` 可按门店设置小盘、大盘的空盘重量；重量未提供前留空并保持关闭。启用后，按 2026-10-25 的决定，每次打开新的称重商品默认选中小盆（ボウル・小），不沿用上一碗的大盘。盘型标题旁以紧凑小字提示“大きい場合は「大」を選択”，遇到大盘时由收银员切换；稳定时自动按“总重 − 所选盘重”得到计费净重；更换盘型或修改设置须重新称量。使用软件扣重时，不再使用秤的去皮键或自动去皮。手填入口输入已经扣除容器的净重，不再扣一次。已加入会计的餐份保留当时的盘重快照。

| 付款情况 | 厨房票 | 出品票 | 顾客叫号票 | 收银条 |
| --- | --- | --- | --- | --- |
| 一人买一碗 | 1 | 1 | 1 | 1 |
| 三人三碗，一人付款 | 3 | 3 | 3 | 1 |
| 三人三碗，分别付款 | 3 | 3 | 3 | 3 |

三个制作位置统一标为 1、2、3：冰箱贴票栏、灶头／锅位置、装盘位置的编号必须一致。通常同时使用两个，第三个备用；不能因为有五个灶头就让一个人同时照顾五份。这里的制作位置编号与顾客取餐号是两套不同标识。

1. 收银员一次接待一组，按菜碗摆放顺序逐碗称重，确认汤底／味道、辣度、麻度、加面和厨房追加食材。每碗分别输入；相同重量与口味也不能合成一个制作对象。特定一碗的要求填入该碗厨房备注，全单备注适用于全碗。
2. 确认付款完成后确定订单。每碗依次打印厨房票、出品票、顾客叫号票，三张使用同一号码；全部碗打印完后，最后打印一张整单收银条。单碗共4张，三碗合单共10张。
3. 处理一碗就把厨房票和出品票分别固定在该菜碗外侧，不重叠，并把同号叫号票交给这一碗的顾客，然后处理下一碗。付款人拿收银条；一人买多碗可以保管多张叫号票。
4. 菜碗带票进入“已付款待制作区”。位置全满时继续等待，不能把下一份票叠贴在使用中的编号栏。
5. 厨房确认空位，先把厨房票移到冰箱对应栏，把同号出品票贴到对应出品区的托盘上，核对两票同号后再把食材倒入对应锅，之后回收选菜碗。制作时间与配方引用已经批准的制作手顺书／早见表，不由接客培训重新规定。
6. 出锅时，从 1 号锅装入装盘区 1 号位置托盘上的成品碗。料理人员和出品调味人员核对冰箱厨房票与托盘出品票同号。出品人员按出品票核对口味、辣麻、加面、加料和备注，完成调味与检查，再把带出品票的整盘移到待取餐区。交接完成后撤下厨房票，不再移贴托盘。
7. 装碗、双票照合、调味检查、托盘搬出全部完成，才释放该制作位置。禁止锅已经接了新单，而同位置的碗或票仍属于上一单。
8. 料理和出品检查完成后，在 POS 出餐面板点该碗的“呼び出す”，按独立取餐号叫号；厨房也可在原厨房屏操作。核对顾客叫号票与托盘出品票，实际交出后才点“お渡し済み”。合单里的各碗可以分别叫号和交付；全部交付后结束整单。

2026-10-19 已确认的简化操作：POS 只显示“提供待ち／お渡し”两栏，不要求员工逐单点“开始制作”。付款后自动进入等待队列；出餐、叫号和实际交付仍由员工确认。此面板代码与验证已准备，需另行发布并在后台按门店启用。iPad mini 默认收起，点开即可处理之前的碗，正在点的下一单保留；大屏可选择常驻显示。误点的叫号或交付在15秒内可撤销，但后续已有操作时需按最新状态核对。

纸与粘胶不接触料理。正式使用前必须测试厨房票从菜碗转到冰箱、出品票从菜碗转到托盘时揭贴是否仍清晰牢固；无法稳定揭贴时，冰箱编号栏改用夹票条，保持每碗两张内部票的同号对应关系。

## 异常与恢复

| 场景 | 执行要求 |
| --- | --- |
| 未付款、支付失败 | 不送厨房；未付款菜碗与已付款待制作区分开。 |
| 会计请求结果不明 | 使用“元の会計結果を確認”，核对原交易；不创建新付款订单。恢复记录在同一终端持久保存。如果确实未保存，可选择“未保存の場合だけ無効化”；服务器先与原请求串行核对，已有订单不会作废，未保存请求会留下防止迟到请求再次入账的标记。已经收过款时仍须负责人确认精算，不会自动退款。 |
| 缺纸、断线、打印中断 | 检查实物和发送状态，补打缺失的票；保留原号。发送成功不等于纸张实际输出。 |
| 票已发出但结果不明 | 不自动重印。员工先核对实物，再明确选择补打，撤掉重复有效票。 |
| 换锅／换灶 | 目标位置必须空闲，一次只转移一份，票与食材同步对应。 |
| 票脱落或破损 | 暂停该份流转，确认料理和原订单对应关系后补打；不能凭外观猜。 |
| 顾客丢叫号票 | 负责人核对收银条关联号码、每碗内容和交付状态，避免重复交付。 |
| 合单分批出餐 | 逐碗叫号、逐碗交付，不用等整组全部做好。 |
| 顾客未取 | 保留待取餐状态，人工重复叫号；不能仅因叫过号就结束订单。 |
| 改口味、加料、取消、重做 | 先通知厨房并确认进度，由负责人按既有政策处理。旧票明确撤销；不得保留两张互相矛盾的有效厨房票。 |

当前实现不新增付款后改单或重做按钮。培训必须把这些操作写成负责人处理，并引用实际批准的政策，不能教员工使用不存在的系统功能。

## 如何放进现有手順書

管理入口 `/os/procedures`，门店阅读入口 `/store/procedures`。新增“加盟店研修テンプレート”提供“まぁ麻 店内接客・会計・厨房引継ぎ”完整下书和“开店前确认”整备用下书；点击后进入现有编辑器，不会自动写入正式数据库或发布。

流程书使用“接客・提供”类型，独立于商品配方。模板包含 11 个步骤：岗位布置、逐碗受付、付款、配票、等待、移票投入、装碗照合与调味、叫号交付、异常恢复、変更／キャンセル／重做、实演验收。选定品牌和适用门店，补充冰箱、灶位、装盘区、三种票样的实际照片后保存。负责人复核并发布，门店才能在阅读页看到；复制给其他加盟店前确认其设备与位置布局。

使用步骤正文写“谁、何时、在哪里、做什么、完成条件”，注意事项写停止条件和常见错误；图片使用现有 mediaUrl 字段。商品、配方、加热与保存规则引用商品主数据和已有制作内容，不重复建立另一套配方。

现有系统有版本编号和发布／草稿状态，但本次不声称已经有培训考试、员工已读签收、合格证或培训完成台账。最后一个实演步骤是培训验收清单，结果需由指导者按门店规定记录。

## 实演验收

指导者先示范，员工轮换收银、厨房、取餐岗位。演练单碗、三碗合单、三碗分别付款、相同口味与重量、第四碗等待、缺纸、换锅、丢票、单碗先交付、改单／重做负责人交接。

验收要求：每份料理与顾客票号匹配；无未付款投入；无制作位双重占用；无重复收款；完成与交付状态区分正确；不明情况能停止并找负责人。不能把阅读完手顺书等同于培训合格。

## 实现和上线边界

一笔 store_customer_orders 保存一次付款；每碗独立 item、pickup_code、制作任务和 handed_off_at。原有历史订单不重编号，Web予約／外卖不改为这套 POS 票据模式。编号按店连续分配，不在午夜重用；真正离线现金订单使用带 O 前缀的稳定号码，同步后不换号。

需先应用 `db/migrations/20261015_pos_bowl_tickets.sql`，再上线对应代码。迁移仅加表、列和索引，不删除或重编号历史数据。桜並木店当前已启用收银打印、关闭远端厨房自动打印；新逐碗票据从收银打印机输出，不依赖远端厨房打印开关。

已保存的旧两票批次按原顺序恢复，不插入出品票或错用文档编号。新批次整批持久保存，出品票可单独补打。打印恢复快照保存在原收银终端，以客户端交易 ID 保持同步前后的文档身份；真正离线时不依赖在线厨房屏，恢复联网后保留原票号并核对已同步订单状态。更换或清空终端前要先处理未确认会计和未发送票据；跨终端顾客叫号票恢复不是本次已实现能力。上线验收还需要真实打印机、粘胶票纸、断纸场景及现场播音，不以隔离测试代替。

2026-10-25 容器用语统一：选菜用的深口盆在日语界面称为「ボウル」。POS 标题为「ボウルのサイズ」，按钮为「小／大」；后台空盆重量设置、已选重量摘要使用「ボウル（小）／ボウル（大）」。这只是显示用语调整，预设 ID `small` / `large`、既有重量、默认小盆与扣重规则不变。
