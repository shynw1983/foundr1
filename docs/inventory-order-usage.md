# 库存、配方与订单联动

入口：`/os/inventory` 的「注文・在庫連動」「製造・店舗間移動」；菜单的 SKU 关联编辑中可维护用量配方。

## 操作流程

1. 维护稳定 SKU。进口商品每次购买包装不同，可复用包装模板并在购买和实际入库时确认本批规格；历史记录保存规格快照。重量与运输重量不能混用。
2. 菜单和选项分别关联配方：准确用量、预计用量或未测定用量。配方以每份或实际计量为基准，修改生成新版本。明确不耗用独立 SKU 的选项可配置空配方；缺少配方不等于零耗用。
3. 每家店设置 SKU 的出库位置。仅有一个有效位置时可使用该位置；多个位置必须指定。先实际清点库存，再在店铺设置里启用订单联动，默认开始制作时扣减，也可选择有效成交时点。启用前的历史订单不补扣。
4. 半袋可输入 `0.5 袋`，按已确认的关系换算为清点单位，例如 `1 袋 = 20 个` 时为 10 个。不同包装的混合库存须以个数、重量等一致单位清点，不能用今日规格重算历史批次。
5. 购买不加库存。实际纳品后记录入库，确定数量才增加账面库存；不知道总量或规格时保留未知，并由下一次真实清点恢复起点。
6. 关联有效订单按原始订单 ID 幂等扣减。准确用量影响账面余额；预计和未测定用量保存在耗用记录及预测中，实数清点保持独立。开始制作前取消不扣，已制作后取消或退款保留食材耗用。
7. 下次清点保存清点起点、期间入库、订单耗用、理论剩余、实际剩余和差异，然后以实数建立新起点。差异包括漏记、替代、损耗和制作偏差等可能原因，不自动认定全部为损耗。真实清点和预测保留各自依据。

## 无固定用量的预测

未测定原料使用两次真实清点之间的减少量，结合已记录入库、准确耗用、其他库存变化和关联订单份数，学习平均耗用。没有有效区间、单位变化、订单未映射、存在未确认入库或未计量制造时，不能生成可靠的耗尽日期。配方版本集合变化时，旧模型不会重算新配方或混合旧版订单；预测与精确账面库存分开展示。

可继续使用「足りる・少ない・なし」粗略清点，减少日常录入负担。粗略观察不会伪装成实数清点，也不会训练精确耗用模型。

## 中间产品和加盟供应

底料、预制品作为独立 SKU。制造记录按冻结配方版本扣原料，并按本次实际产量增加成品；原料未知保持未知。成品被菜单使用时扣成品 SKU，避免重复扣原料。店间移出先扣来源，处于在途；收货店实际确认到货后才增加目标库存，可分批到货。成本和供货价分字段保存，此动作不产生付款。

商品公开范围继续由现有商品总表品牌与店铺授权控制。总部管理配方与包装模板，加盟店只能读取自己可见 SKU 的配方；隐藏原料会脱敏。目标店必须获准访问转入商品。

## 外卖订单、冲突与验证边界

POS、Web予約、桌台原始订单使用结构化菜单和选项 ID。无法确认菜品、选项或数量的外卖导入保留待处理问题；待确认原单界面可按完整原单手工指定菜单、每份选项数量、份数，并确认原单身份。外部导入的完成/采集时间不能代替实际制作时间；没有可信制作标记的订单，还须确认实际制作时间，迟到原单不会重扣已覆盖该时点的清点余额。禁止按相似名称自动精确扣库存。本阶段外部来源的人工映射只覆盖经确认的这一单，不是持续自动匹配规则。

账面更新采用版本检查和幂等键；重复事件不重复扣减。并发清点、入库、制造后旧草稿会要求重新确认。制作快照保留原制作明细，退款后的重试也不会丢失实际耗用。迟到的旧订单保存历史，但不会再次扣已覆盖该时点的新清点余额。订单与厨房主流程不因库存异常而失败，问题可在库存界面查看和重试。

自动联动默认关闭。上线验证不创建真实采购、销售、付款或库存调整；业务回归在隔离数据库完成，线上只读验证配置与接口。
