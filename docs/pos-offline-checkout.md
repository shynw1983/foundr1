# POS オフライン会計

Android Store App の `/store/pos` は、オンラインで一度読み込んだ店舗について最大24時間、現金の応急会計を行えます。

## 対応範囲

- 現金の店内・持ち帰り注文
- 端末内への注文保存
- Bluetooth / USB / Star プリンターへのレシート・厨房票印刷
- 通信復旧後の自動同期
- クライアント注文IDによる重複防止

オフライン中は会員、ポイント、クーポン、割引、テーブル会計、オンライン決済を利用できません。未同期注文がある間は日次レジ締めを実行できません。

## 保存と同期

POS のメニュー、価格、店舗設定、レジ状態は IndexedDB に店舗別スナップショットとして保存されます。オフラインで開始した注文には UUID と `O` で始まる取扱番号を付け、印刷物には `オフライン未同期` と表示します。通信中断時の二重登録も防ぐため、通常の POS 会計も最初の送信から同じ UUID を使います。

同期APIは `offlineClientOrderId` を `store_customer_orders.offline_client_order_id` に保存します。同じIDが再送された場合は既存注文を返すため、通信切断やアプリ再起動による二重登録を防ぎます。

同期時に現在のメニュー金額と会計時金額が異なる場合は自動登録せず、POS に管理者確認エラーを表示します。

## 店頭ですぐ渡す商品（2026-11-03 実装）

店舗 POS の商品設定 `fulfillmentMode` は `prepare`（調理・提供待ち）または `immediate`（会計時に渡す）です。未設定は従来どおり `prepare`、麻辣湯のボウルは常に `prepare` です。飲料という種類だけで自動的に即渡しへ変更しません。手作りドリンクは従来の調理・提供フローを保てます。ボウルに付けた飲み物・味・追加食材などの選択肢は、そのボウルの内容として保持します。

新しい POS は `posFulfillmentPolicyVersion: 1` と、読み込んだ店舗メニューに基づく各明細の提供方法を注文・復旧記録へ保存します。オンライン復旧時は同じ注文 ID を使い、保存時のメニュー revision・提供方法と現在の信頼できる設定を検証します。変更がある場合は自動的に解釈し直して再登録せず、元の会計の確認を求めます。店内・持ち帰りのどちらもこの検証対象です。メニュー・価格の反映は引き続きスタッフの手動更新です。

即渡し商品のみの会計では厨房・出品・お客様番号札を作りません。商品の金額・数量・選択内容はレシートにすべて残り、`O` 番号は会計の照合番号として扱います。レシートを出す場合は端末内の文書バッチを送信前に保存します。結果不明・送信失敗の文書は復旧や同期だけでは再送せず、実物の確認を必要とします。ボウルを含む会計ではボウルの番号札・調理内容を保ち、単独の即渡し商品だけを調理伝票から除外します。

この節は実装契約です。Web の公開、端末に残る古いオフライン注文の扱い、実際のプリンター出力はそれぞれ別に確認します。

## アプリシェル

Service Worker は、オンラインで利用した `/store` 画面と対応する Next.js 静的ファイルを保存します。Android App を完全にオフラインで再起動するには、対象バージョンへの更新後に一度オンラインで `/store/pos` を開いてください。
