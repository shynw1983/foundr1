# 应用更新提示与版本隔离

OS、Store、Staff、Member、Studio 使用不同的应用标识与内容版本。网页刷新提醒不再比较整个项目的 Git SHA 或 Vercel deployment ID；Android APK 继续使用各自 `/downloads/{app}/version.json` 的版本与包身份，不参与网页版本哈希。

## 版本生成

`npm run dev` / `npm run build` 在启动 Next 前自动运行 `scripts/app-web-versions.cjs`，生成被忽略的 `lib/generated/app-web-versions.json`。保留原有的 prebuild 流程。单独调用 Next CLI 前也必须先运行生成器；不要复用历史生成结果。运行时只读取构建产物，Next 配置不导入生成器，不扫描源码，也不访问数据库生成版本。

每个应用的版本由其入口、实际传递引用的模块、API 实现及对应静态资源的路径和内容组成。真正被多个应用使用的代码或 API 变化，会更新所有实际消费者的版本。只修改 OS 页面不会使 Store 更新；只修改 Studio 源码、AI API 或 APK 下载文件不会使 OS/Store 更新。生成结果本身不纳入哈希，避免循环与跨应用连带。未解析的本地模块及未知 API 引用会中止生成；现有可选 `/api/sns` 的 404 探测有单独说明，若将来增加该接口则纳入正常依赖。

公共资源路径先标准化；通用跳转 `/${href}` 和嵌套路径片段 `/${id}` 不会穷举整个 public 目录。遍历结果再次排除下载目录、安装包及其他应用专属标识，构建时生成的无关 public 文件也不会改变应用内容版本。

正常发布无须手工改版本号。环境配置或外部运行条件变化、且确认需要用户刷新时，可在该应用入口显式引用的 `release-revision.json` 中新增或更新一个明确的 `revision` 值，作为该应用的受控版本输入。未被入口引用的普通 JSON 或草稿不会纳入版本。不要修改全局部署标识冒充应用更新；没有客户端变化的数据更新仍沿各业务的实时更新协议处理。

内容版本仅决定刷新提醒。同一 Next 项目的静态资源、框架运行时和部署仍共用，不代表应用已经拆为独立部署；保留 Next 的正常 build ID，不将其固定为应用内容哈希。

## HTTP 与推送契约

- `GET /api/app/version?app=os|store|staff|member|studio` 返回 `{ app, version, shortVersion, checkedAt }`，无缓存。未指定应用的旧地址固定为 OS；`/api/store/version` 保持 Store 固定别名。
- `GET /api/app/version/realtime-config?app=...` 只返回该应用公共版本频道的配置，频道为 `app-version-{app}`，事件为 `app.version.updated`。不订阅订单、员工通知或其他门店业务频道。
- 事件带应用标识，但仅作为失效信号。客户端只接受本应用消息，然后读取本应用端点；事件中的版本不能直接成为界面上的更新结论。
- `POST` 只发布服务端当前应用版本，忽略客户端提交的版本内容。保留有效员工会话校验；旧 `STORE_VERSION_NOTIFY_SECRET` 仅允许 Store，选配的 `APP_VERSION_NOTIFY_SECRET` 可用于受控发布钩子。公共 GET/config 无员工、门店或业务记录；POST 鉴权用于防止匿名广播。
- 页面会按应用与版本在会话内发布一次，只有成功响应才记为已发布。旧 `store-version / store.version.updated` 混用广播停止。所有业务推送、权限、操作权、打印及结账协议保持各自边界。

## 协调器与读取预算

这是非紧急版本元数据，遵循[实时更新规范](realtime-refresh-policy.md)的低时效档位。每个页面运行实例内，按应用及端点共享一个协调器；不同设备独立核对。资源为全应用公共版本，不包含账号或门店读模型。

- 本应用频道订阅成功且实际连接正常：推送触发读取，并每 15 分钟轻量核对，弥补连接正常但漏消息；无事件稳定时最多约 4 次版本读取/小时。
- 订阅不可用或不完整：5 分钟起步补查，稳定 HTTP 情况约 12 次版本读取/小时；配置获取失败单独退避，不影响权威版本检查。
- HTTP 失败使用独立指数退避，基础 5 分钟、通常上限 60 分钟，并遵守更长的 `Retry-After`。获取响应及解析正文均有 10 秒超时。401/403 停止相关自动重试，到明确恢复或重新建立运行实例后再校准，不改用其他身份。
- 初次进入、重新订阅、focus/pageshow/online/恢复可见会校准；相邻唤醒合并。隐藏时暂停常驻读取；退出取消自身请求及订阅租约，不断开其他消费者。
- 单个版本读取在途时，事件记为待补读，完成后再读，不能吞掉新事件。旧实例/已退出页面的晚响应无效；跨应用响应和事件被拒绝。

预算不包括实际发布/恢复/推送引发的必要读取；实时配置获取和订阅失败也单独有界。订阅正常、HTTP 失败、订阅失败各自维护状态，不把 socket connected 当作资源完整。

## 用户行为与迁移

新版本只显示非阻塞提醒，由用户点击刷新。后台核对、推送和恢复不调用 reload，不清空购物车、编辑内容、人工菜单或价格。

仍运行旧网页的客户端，首次从全局部署版本迁移到独立内容版本时可能出现一次正常更新提醒。刷新后才具备新协议；不能把服务端已部署描述为所有旧设备已接受。浏览器交互、真实订阅、已安装原生壳和实体设备验收分别记录。
